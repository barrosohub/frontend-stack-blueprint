# Frontend Stack Blueprint 2.0 modernization

## Goal

Restore the repository as a current, deterministic frontend reference as of
2026-07-30 while preserving its agent-native contracts and capability-gated
architecture.

## Required outcomes

1. Update the canonical stack to currently supported major lines:
   TypeScript 7, React 19.2.7+, React Router 8, Vite 8, Vitest 4, Node.js
   22.22+ on maintained releases, Prisma 7, and current validated package
   versions.
2. Replace obsolete configuration:
   - remove deprecated TypeScript `baseUrl`;
   - account for TypeScript 7's explicit type environment;
   - use Vite 8's Rolldown/Oxc model and `resolve.tsconfigPaths`;
   - do not publish production source maps by default.
3. Make package-manager provisioning work with and without bundled Corepack,
   and pin the validated pnpm release through `packageManager`.
4. Align the UI contract with current shadcn behavior:
   Base UI by default, Radix UI as a supported alternative, and React Aria as
   an accessibility-oriented alternative.
5. Treat React Compiler as stable and capability-gated rather than future
   technology.
6. Resolve internal contradictions:
   - functional components versus class-based Error Boundaries;
   - CI authority versus mandatory local hooks;
   - useful inference versus universal explicit return types;
   - reuse guidance versus premature two-occurrence abstractions;
   - accessible primitives versus claims of automatic product conformance.
7. Replace unbounded or ambiguous `latest` guidance with a tested/current
   version plus an explicit compatibility policy.
8. Keep `stack.yaml`, schemas, profiles, generated entrypoints, documentation,
   templates, fixtures, changelog, and package metadata synchronized.
9. Record primary-source research and migration guidance in the repository.

## Compatibility policy

- `current` means the exact version validated by this blueprint release.
- `min` means the oldest supported version in the validated major line.
- New project instructions install the current supported major, not an
  unbounded future major.
- Runtime support includes only maintained Node.js release lines even when a
  package's engine range technically accepts an EOL release.

## Verification

- `pnpm install --frozen-lockfile`
- `pnpm check`
- repository-wide stale-reference scan
- two-axis review against repository standards and this specification
